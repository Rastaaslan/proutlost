# P008 native automatic fragment rate recovery proposal

Defect `P008-D-F8-AUTO-CONTINUATION-RATE-CLOCK`. Source-only proposal for sequential integration by the sole root owner, based on the current R6 per-file preimages. No canonical/remote files were changed here. The four production files are `AdminPageState`, `AdminQueryDispatch`, `DirectorScreen`, and `DirectorClientPacketGateway`. One new standalone regression class accompanies them. `P008_F8_AUTO_RATE_SOURCE_DELTA.json` lists exact before/after hashes; preserve the existing sources, worlds and negative R5/R3 proof, check every preimage and inspect the patch before integration. Do not replace a later source blindly.

Before correction, the client40-tick automatic continuation can reach a server that has advanced only39ticks. The authoritative REJECTED/RATE_LIMITED reply then clears the partial document. Increasing a controller's manual wall cadence cannot fix an automatic continuation. The proposed native client retries only a marked automatic transport-fragment read after an exact correlated typed REJECTED result with the single RATE_LIMITED reason. It preserves the query's actor/panel/filter/cursor/expected revision/limit, the assembler and exact snapshot stamp; a new request ID goes through the normal gateway and reply fence. No server gate or wire DTO changes.

Each document permits at most three quota retries, with2/4/8-second monotonic backoff plus the existing client tick fence. The first refusal of a cursor starts a30-second monotonic deadline that a resend cannot reset. Actual successful fragment receipt ends that cursor episode; the per-document retry count persists until hash-verified semantic completion. This permits large valid documents to take more than30seconds across multiple successful fragments while keeping a refused cursor bounded. Server40-tick admission and60-second cursor TTL remain authoritative. A local deadline is never a server freshness proof.

Every other refusal, failed/uncertain read send, exhausted budget, expired episode, invalidated/context-changed/closed/new session or explicit new query remains fail-safe. The unchanged assembler enforces original document hash, identity, order and exact revision/tick/durable cut. Fresh SEARCH, semantic NEXT and empty global-directory warming reads do not acquire automatic retry behavior. Product UI simply reports a temporary read delay or an explicit retry requirement.

`AdminPageState.ContinuationRetryView` is an evidence-only immutable typed view. It exposes the exact refused query/session, new in-flight RID, ordinal/bounds, monotonic observed/backoff/deadline values, partial hash/received bytes and snapshot cut. It neither mutates state nor acknowledges or authorizes a response. A future separately versioned QA observer/harness must correlate this view with the actual refusal and subsequent exact new-RID continuation before tolerating that one transient result. Frozen R3 remains RATE-terminal and its failure remains retained.
