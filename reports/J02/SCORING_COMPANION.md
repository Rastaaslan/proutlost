# Compagnon de scoring — API 1.0.1

Baseline qualifiée Work importée exactement (49 fichiers API/testkit + 13 documents), attestée dans `API_BASELINE_ACK_1.0.1.json`. Aucun contrat commun modifié indépendamment. Les cinq schémas normatifs et le wire EventDefinition restent inchangés.

`DefinitionLoader.reload` accepte ensemble `data/<namespace>/director/{events,chains,scoring}/<path>.json`. Les limites d'octets et de documents portent sur l'ensemble. Le compagnon suit le schéma fermé `scoring-metadata.schema.json`. Champs obligatoires : schema_version=1, definition_id, definition_revision, content_revision, calibration. L'API 1.0.1 n'autorise les profils que pour les événements : un compagnon ciblant une chaîne est rejeté explicitement.

Champs optionnels : context_affinities (IDs enregistrés vers affinités unitaires), region_traits (RegionTrait), tension_affinities (GlobalTension), desired_local_intensity (unité finie [0,1]), habitation_sensitive (booléen). Les références @test sont résolues avant une seconde validation du schéma, uniquement avec provenance DEFAULT_FOR_TESTING. La fixture utilise les valeurs du profil authentique inchangé.

La composition injecte une map immuable ResourceId -> ContextBinding(Condition, UnitValue weight). Chaque condition est validée avec les mêmes registres typés que les conditions des événements. Aucun nom de contexte n'est interprété : `test:players_present` est un ID synthétique dont le test fournit explicitement PlayersPresent(1) et poids 1. Aucun contexte synthétique n'est enregistré dans les ressources runtime. Le constructeur sans map enregistre zéro contexte et rejette toute référence contextuelle non résolue.

Projection exacte vers DefinitionScoringProfile : DefinitionRef contient ID/révision/hash canonique du DTO événement compilé ; contextAffinities conserve prédicats, poids et affinités ; regionAffinities/tensionAffinities conservent les valeurs ; desiredLocalIntensity est Optional<UnitValue>. Un habitation_sensitive explicitement true applique la sensibilité à toutes les familles déclarées de cet événement ; false/absent donne l'ensemble vide. Les autres absences donnent collections vides/Optional.empty ; J03 utilise les neutres de configuration centrale selon son contrat. Le constructeur normal déclare les quatre features neutres depuis score.neutral_feature ; la surcharge expose leur déclaration explicite à la composition.

Le hash de profil cadre les octets canoniques du compagnon résolu, de l'événement compilé et des affinités contextuelles résolues. Le hash de génération combine catalogue, configuration, neutres, registre explicite de contextes (prédicats/poids inclus) et compagnons canoniques triés. Une modification des seuls profils change la génération ; whitespace et ordre des fichiers ne changent pas le hash. Régression ou réutilisation divergente de content_revision est une erreur ; les tombstones sont conservés après retrait, sous borne explicite.

Toute la compilation est locale avant publication. Un unique AtomicReference<State> contient le CatalogSnapshot avec scoringProfiles ET les historiques de révisions définition/compagnon. Un unique CAS publie cet ensemble. Erreur de définition, de compagnon, de projection ou course perdue : aucun élément du candidat n'est publié. Les snapshots déjà retournés conservent leurs profils immuables. ScoringMetadataCompiler.prepare reste un helper pur, et non un second port publié.

Validation réelle : 101 assertions scoring (préparation, projection API 1.0.1, invalides, générations combinées, suppression/tombstones, changements metadata-only, pinning, deux writers concurrents divergents). Commandes, plafonds, préflights et hashes : TEST_RESULTS.json. Évaluation J03, rendu/audio/physique/serveur : NOT_RUN, responsabilités d'intégration distinctes.
